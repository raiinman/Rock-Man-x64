# Local PS1 research workbench

## Purpose and implemented tools

The expanded private workbench organizes the existing research setup around the port's missing evidence. It is an original local application, separate from the native game. This repository publishes its capability description, not its implementation or private captures.

- **Capture explorer:** five retained sessions cover the SPU baseline, scheduling and a saved scheduling summary, plus the completed recorder calibration and synthetic A0:49 occurrence. Inspection checks retained identities and bounded shapes; it does not launch a fixture. Filters, ordered-event views, register snapshots and access-to-delayed-result associations preserve their distinct evidence roles. Unavailable transferred payloads stay unknown.
- **Comparison:** different fixtures or incomplete identity information produce a descriptive comparison, not a conformance result. Unmatched events are not zero-valued observations.
- **A0:49 review:** declared target, known masks, sources and occurrence order control branch-specific checks. A different or partly known target cannot establish the selected wrapper's readiness path. An edited or invalid frame clears the prior displayed result. Missing parser, ABI and reaching-state evidence remain explicit.
- **Owner lifecycle review:** a separate declared snapshot checker identifies cancellation/completion, stop/fault, worker, callback and message obligations. It preserves the [source-only S2 NO-GO](../../docs/status/decisions-and-handoff.md#s2-lifecycle-decision--october-23), including when supplied snapshot conditions are favorable. Worker exit is insufficient evidence of whole-owner retirement.
- **Address and register lab:** segment arithmetic, region and alignment checks accompany known-mask decoding for selected GPU, DMA, SPU and IRQ fields. Unknown bits remain unknown; calculations do not read MMIO or certify memory-map behavior.
- **Research library and notebook:** allowlisted original reports, private multi-project notes, revision conflicts, atomic saves, workspace backups and handoff drafts support future PS1 investigations. Exports require review before sharing.
- **Bounded plans and instruments:** a plan export records a question, input identity, event/time bounds and watchpoints. It is not a runnable collector. The existing two SPU fixtures and graphical debugger retain explicit manual launch actions. A0:49 replay is not provided.

## Verification and limits

The completed application verification passed 34 Python host/HTTP checks and three JavaScript analysis suites. Host checks cover retained-source rejection, identity-sensitive comparison, unknown-bit preservation, dispatch binding, observation order, malformed input, projection of exports, notebook persistence and stale-write rejection. HTTP checks cover cross-origin and unconfirmed launch rejection, allowlisted reads and capture export. Browser verification covers retained inspection, comparison, edited-frame invalidation, report loading, notebook saving and reload, plus a pending callback after declared worker exit. These checks exercise the research application; no new BIOS, emulator, native game or sealed validation run is claimed.

The local service binds to loopback and offers no arbitrary command runner or general file browser. Notebook revisions reject a stale tab rather than silently replacing newer notes. Installed-tool file presence is reported separately from running-process health. Private source receipts and test artifacts are not independently reproducible from this documentation-only repository.

## Immediate use for the boot investigation

The [retained synthetic A0:49 occurrence](A049-RECORDER.md) remains useful for inspecting the existing collector's distinctions, not for filling the game's unknown GPU fields. The [handoff](NATIVE-HANDOFF.md) still needs identified game-time dispatch, ordered state producers, parser position, outstanding completion and the caller's consumer obligations. A favorable manually declared checklist authenticates none of those sources.

For the separate controller blocker, use an identified owner/generation and new source-level transition evidence to resolve the first outstanding obligation. A declared snapshot cannot supply an absent cancellation contract or retirement transition. The workbench neither changes the game implementation nor enables S2, retries the blocked initializer, terminates native owners or substitutes a different execution route.

The next useful input remains a new bounded response from the development agent tied to its current artifact and question. Neither dashboard expansion nor successful host tests establish that Rock Man x64 boots.
